# S3 uploads

The AWS extension is bundled for bucket `cloudwiki01` (ARN
`arn:aws:s3:::cloudwiki01`) in `us-east-2` (Ohio). S3 is disabled until
`MW_S3_ENABLED=1`. Existing files continue to use local storage while disabled.

Fill `aws_secret_access_key` in the ignored `docker/secrets/farm.json`.
`aws_access_key_id` has been populated with the supplied ID. Do not commit this
file. For production, use the `farm.json` in that deployment's
`FARM_SECRETS_DIRECTORY`. Temporary credentials also accept `aws_session_token`.
For an IAM role, omit both credential fields so the SDK uses its default chain.

Keep S3 Block Public Access enabled and Object Ownership set to Bucket owner
enforced. All objects remain private; MediaWiki serves files through
`img_auth.php` and applies the wiki's read permissions. Do not grant anonymous
bucket access. Each wiki has its own prefix, for example
`testwiki/a/ab/Example.png`, `testwiki/thumb/...`, and `testwiki/deleted/...`.
Uploads keep the existing two-level hashes and deleted files use three levels.
`MW_S3_PREFIX` adds an optional prefix before the wiki directory. Development
uses `development/`; production uses `production/`.
UserProfileV2 avatars use a separate S3 backend under each wiki's
`upv2avatars/` directory. Their `img_auth.php` route checks wiki read permissions.

Attach [s3-iam-policy.json](s3-iam-policy.json) to the credential's IAM identity.
This grants access to this bucket only. It does not grant bucket creation,
bucket policy changes or public access changes. The bucket must already exist.

Before enabling:

1. Verify the credentials and bucket region with an authenticated S3 client.
2. Take a coordinated backup and stop upload writers, including background jobs.
3. Export the active Docker uploads volume. Copy its contents, preserving each
   wiki directory and all archive/deleted/thumb/temp files:

   ```sh
   aws s3 sync /path/to/exported/images/ s3://cloudwiki01/production/ --region us-east-2
   ```

   Use credentials configured privately in the AWS CLI. Do not pass an ACL or
   `--delete`. Compare local and remote contents before switching storage.
4. Set `MW_S3_ENABLED=1`, `MW_S3_BUCKET=cloudwiki01`, and
   `MW_S3_REGION=us-east-2`, and `MW_S3_PREFIX=production` in the production
   environment file. Rebuild immutable
   images to include this extension; recreate every PHP/worker service with
   the new environment. Bind mode already reads the bundled source.
5. Verify an upload, thumbnail, archived revision, deletion/restore and private
   wiki access before reopening writes.

The current backup/restore and DataDump ZIP tools archive the local uploads
volume. They do **not** include S3 changes. Arrange separate bucket backups and
an S3-aware ZIP export before relying on those features after cutover. Enable
bucket versioning and define retention separately. Reverting to local storage
after S3 writes requires copying the current objects back while writers are
stopped; toggling the flag alone would leave new files unavailable.

Upstream installation and configuration:
[MediaWiki Extension:AWS](https://www.mediawiki.org/wiki/Extension:AWS).
The pinned revision and local compatibility patches are recorded in
`mediawiki/extensions/AWS/SOURCE.json`. Dependencies have their own lockfile;
shared HTTP library versions match the core lockfile.
